### CR-023: Assessment-Model Federation Reconciliation (New Register, R7/R8/R9)

The reconciler stops hard-coding the organization. `ORG` is retired as an assumption and becomes `DEFAULT_ORG` - a fallback used only for register rows that declare no `organization` of their own. Every URL the reconciler builds for a register row (the API, `raw.githubusercontent`, the git-trees and git-refs routes) is built from that row's `organization`, so one reconciler spans organizations (`Assessment-Models`, `technehub-labs`) with no hard-coded assumption; the catalog-portfolio population predates per-row ownership, carries no organization field, and falls back to the default, so R1-R6 behave exactly as before with no register row touched.

New register `registers/assessment-model-portfolio.yaml` (v1, 8 rows): the federation's maturity-model population, each row binding a canonical id published by the upstream reference catalogue to the repository and immutable release that publish it (repo, organization, canonical_id, canonical_version, state, release, ratified). The seven Assessment-Models models are published; the DEA-owned EA-capability model (technehub-labs/maturity-model-ea-capability) is recorded `pending` because its repository is published in parallel - and `pending` is not an exemption: the reconciler still reports the unresolved pointer as a finding (R9), which clears by itself when the parallel publication lands.

Three rules added against the federation's canonical reference root (dea-metamodel -> assessment-models/catalog/reference-catalog.yaml and model-relations.yaml). **R7 canonical binding, bidirectional**: every register row binds a canonical id the catalogue publishes, as a maturity-model reference, at the catalogue's own version; and every maturity-model reference the catalogue publishes is claimed by exactly one row (none claims it -> unclaimed canonical model; several -> ambiguous binding). **R8 dangling reference**: every canonical id the register references, and every source_id/target_id of the upstream relation graph, resolves to an id the catalogue publishes. **R9 repo resolution**: every assessment-model row resolves to a repository that exists in the organization that row declares, at the immutable release that row declares. The catalogue is the authority for WHAT version exists; the Assessment-Models registry is the authority for WHERE it resolves; neither duplicates the other, and cross-organization dependencies stay contractual (the reconciler reads published artefacts, it does not require the other org's repository layout to change). The rule bodies are pure functions unit-tested offline in registers/test_reconcile_canonical_bindings.py (21 new tests; 25 total, all passing). Offline mode still enforces R1/R4 and skips the API-gated rules with a printed WARN - it never crashes and never passes silently; the same holds for any rule whose upstream input is unreachable, and a finding never fires on a transport flake (R9 distinguishes a definitive HTTP 404 from a transport failure and from a 403).
