# Entity-System Public Surface

> **Advisory.** Registry of public-facing surfaces (subdomains + their hosted reference data) that are anchored on the OpenDEA General Entity System. Cross-references the entity-system public-surface index used by the federation surface workstream.

The General Entity System governs identity and conformance across the `technehub-labs/*` portfolio. Some entities are anchored on **public surfaces** (subdomains + their hosted references) that consumers reach over the public internet. This document registers those surfaces so that the conformance, identity, and lifecycle rules apply to them as well as to the catalog entities that point at them.

A public surface is registered when one of the following holds:

1. A subdomain of `technehub.com` (or an org-owned equivalent) is registered in the org's DNS as a pointer at a controlled origin.
2. The hosted service is bound to a canonical artifact in a `technehub-labs/*` repo (the artifact is the source of truth; the service is a presentation layer).
3. The artifact is reproducible from the registered inputs via a build script in the same repo (no silent drift; hash-audited when feasible).

### `lists.technehub.com`

The OpenDEA reference registry is the first registered public surface. It mirrors three sources:

1. **IANA media types** (RFC 6838): 2,305 records as of the 2026-10-16 snapshot.
2. **IANA URI schemes** (RFC 3986 / RFC 7595): 451 records (uri-schemes-1 sub-registry) as of the 2026-10-16 snapshot.
3. **ECF 7 x 7 coordinates**: 49 cells from `dea-metaframework/framework/matrix.md`.

The mirror is deterministic, hash-audited, and reproducible from the source XMLs / Markdown via `scripts/build.sh` in `dea-catalog-references`. If the mirror and the source disagree, the source wins; the mirror is regenerated, not edited by hand.

This surface is the read-only lookup target for OpenDEA catalog entities that need to reference a media type or URI scheme; the catalog entities carry the cross-reference as a string (e.g. `application/json`, `https`), not as a hard dependency on the mirror's hosting. The mirror is a **convenience surface**, not a critical dependency.

## Registration discipline

A new public surface lands via a CR-012-aligned change request that names:

- the subdomain and DNS posture (NS provider, target origin, TLS issuer, HSTS posture);
- the source-of-truth repo and the artifact in it;
- the reproducibility mechanism (build script, hash audit, CI gate);
- the conformance gate that guards the build (JSON parse, SHA256SUMS, en-dash sweep, etc.);
- the consumer catalog entities that point at the surface.

The CR is the durable record. The table above is the live snapshot; it is regenerated by the CR's acceptance ritual.

## Conformance gates

A registered surface must satisfy:

- **DNS state is live and documented.** A records at the registered origin; AAAA records where the NS provider supports them (deferred sub-tasks carry the exception, not the rule).
- **TLS cert provisions automatically.** Issuer is Let's Encrypt unless the CR specifies otherwise; cert provisioning completes within 60 minutes of DNS resolution.
- **Build is deterministic.** The build script regenerates every public file from upstream sources; manual edits to the public artifact are forbidden.
- **Hash audit is present.** A `data/SHA256SUMS` (or equivalent) file lists the hash of every public data file; CI verifies the hash on every PR.
- **Cardinal author rules are honored.** No en/em-dashes in any GitHub artefact (D-004); no `;;;` in prose (D-005); the standardization-body embargo applies (substitute SDO-neutral names; never reference the embargoed bodies by name).
- **Snapshot date is committed.** Every public surface carries a snapshot date (e.g. `2026-10-16`) so that staleness is observable.

A surface that fails a gate is not removed; the failure is recorded in the `Last verified` column and a follow-on CR is filed.
